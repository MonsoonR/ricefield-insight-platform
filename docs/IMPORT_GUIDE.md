# 数据导入指南

## 目标

数据导入的目标不是简单读取文件，而是把来源不统一的 Excel 和 GeoJSON 转换为稳定、可追溯、可检查的标准化数据。

## 导入流程

1. 接收原始 Excel 或 GeoJSON 文件。
2. 识别文件类型、工作表、字段和地块编号。
3. 根据指标字典映射字段名称、单位和数值类型。
4. 根据地块编号规则匹配地块。
5. 转换为统一长表结构。
6. 输出标准化数据。
7. 生成导入质量报告。

## 导入契约

正式编写解析器前，需要先明确导入契约：

- 支持哪些文件类型；
- 每类文件如何识别；
- 文件名是否参与指标识别；
- 工作表和表头如何识别；
- 地块编号如何标准化；
- 指标编码如何映射；
- 解析失败如何进入质量报告；
- 原始文件、工作表、单元格如何追溯。

## 临时样例数据处理

开发早期可以使用临时样例数据理解真实文件结构，但临时目录不作为长期工程内容。样例数据后续可删除，因此业务代码、测试和正式文档不能硬编码临时样例目录路径。

如果临时样例数据暴露出稳定规则或风险，应把这些信息沉淀到指标字典、数据模型、导入契约、质量检查规则或测试夹具设计中。

## 质量报告至少包含

- 导入批次。
- 文件名称。
- 成功记录数。
- 缺失值数量。
- 异常值数量。
- 未匹配地块。
- 错误单元格。
- 跳过记录。
- 解析耗时。
- 导入状态。
