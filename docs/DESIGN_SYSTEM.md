# 设计系统

本设计系统是稻田智研平台所有页面的视觉与交互基线。新增或修改页面前必须先阅读本文件；调整视觉风格、新增组件或修改通用样式时，必须先更新本文件，再改代码。页面不得各自定义私有视觉规范。

## 0. 前端技术栈与组件迁移策略

当前目标前端栈为 Vue 3 + TypeScript + Vite + Tailwind CSS + shadcn-vue + Reka UI + ECharts + CesiumJS + Axios；Vue Router 与 Pinia 继续承担路由和状态管理。Ant Design Vue 是待移除的旧依赖，仅在运行时代码仍有引用时分阶段保留，不再作为新增页面或新组件的首选实现。

本轮迁移只清理方向、统一文档和建立组件基础，不扩大第一阶段 MVP 范围，不修改后端 API、数据模型、模拟数据生成逻辑，不恢复 Excel、GeoJSON、PDF、图片导入，也不引入真实客户数据。六页闭环保持为 `/overview`、`/map-twin`、`/plot-detail/:plotId?`、`/metric-compare`、`/warnings`、`/system-docs`。

组件分层策略：

- `src/components/ui/` 存放 shadcn-vue 通过源码方式加入的 UI 原子组件，保持接近上游实现，使用 Tailwind 语义 token 和 Reka UI 可访问性能力。
- `src/components/base/` 存放稻田智研平台的项目语义组件，如 `PageContainer`、`StatCard`、`FilterBar`、`DataTable`、`ChartCard`、`CesiumMapPanel`、`StatusTag`、`MetricValueTag` 等。
- `src/components/base/AppShell.vue` 是当前主布局边界，统一承载浅色侧栏、顶部状态栏和页面内容区；`src/components/workbench/` 是迁移期遗留工作台组件，仍可被已迁移页面引用，但不作为新增基础组件目录。
- 页面优先使用 `base` 组件表达业务语义，不在页面内直接散落大量 `ui` 原子组件；确需组合 `ui` 原子组件时，应优先沉淀到 `base` 层。
- `src/components/ui/` 当前基础组件包括 `button`、`badge`、`card`、`dialog`、`popover`、`scroll-area`、`select`、`separator`、`sheet`、`skeleton`、`table`、`tabs`、`tooltip`、`alert` 和 `toggle-group`；新增组件必须按 shadcn-vue 源码组件方式进入该目录。
- 基础组件迁移优先级：先迁移 App Shell 与 `base` 组件，保持页面 props、事件和数据结构兼容；再逐页清理业务页面内的 Ant Design Vue 标签、弹层、按钮和局部样式。
- 第三轮迁移已完成页面级 Ant Design Vue 控件清理：系统说明、地块画像、指标对比、预警分析和地图趋势组件不再直接使用 `<a-*>` 标签，旧控件兼容样式也已移除。`ant-design-vue` 依赖、`main.ts` 全局注册、`App.vue` ConfigProvider、`styles/theme.ts` 主题配置和 `vendor-antd` 分包仍按迁移期要求保留；只有后续确认全局入口无需保留后，才删除这些遗留项。

## 1. 平台视觉定位

- 稻田数字孪生平台 / 智慧农业监测系统 / 科研展示型业务系统。
- 设计基调：清爽、可信、专业。强调数据可读性、地图与图表可信度。
- 不做营销化 hero、不做酷炫大屏、不堆装饰卡片。仅在场景驾驶舱顶部允许使用一条轻量场景横幅。
- 信息密度适中，优先展示地块、指标、状态、趋势和预警。
- 中文优先。控件文字简洁，避免营销化措辞与旧导入平台残留概念。

## 3. 排版与间距

- 字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 字号阶梯：`12 / 13 / 14 / 16 / 18 / 22 / 28 / 36`
  - 12：辅助说明、表格脚注
  - 13：次文字、副标题、表格表头
  - 14：正文、表格内容
  - 16：卡片标题
  - 18：分区小标题
  - 22：页面主标题
  - 28-36：KPI 大数字
- 字重：常规 500、标题 700、KPI 数字 800
- 行高：正文 1.55、标题 1.3、KPI 数字 1.1
- 圆角：卡片 12px（`--rf-radius-lg`）、按钮/标签 6px（`--rf-radius`）、图标圆 50%
- 阴影：仅一级阴影 `0 1px 2px rgba(15, 56, 37, .04), 0 1px 3px rgba(15, 56, 37, .06)`，不叠加多层。
- 间距阶梯：`4 / 8 / 12 / 16 / 20 / 24 / 32`，页面主体 padding `28px`，卡片之间 `16-20px`。

## 4. 页面布局规范

### 4.1 全局骨架

- 左侧导航：固定 240px，白底 `--rf-surface`，不得使用深色底。
- 顶部栏：固定 64px，白底 + 底部 1px 描边。左侧放当前页面标题与副标题，右侧固定四件套：天气、通知、文档入口、用户头像。
- 主体：背景 `--rf-bg`，内边距 `28px`，使用 `flex column`，块间距 `20px`。
- 不使用深色背景大屏样式。

### 4.2 数据页面三段式

所有数据页（除地图与系统说明）按这个顺序：

1. **筛选区**：`FilterBar`（指标对比、预警分析、地图、地块画像必备）。
2. **KPI 行**：4 个 `StatCard`，等宽。
3. **主可视化区**：`ChartCard` 或 `CesiumMapPanel`。可与右侧次级面板组合，主图占比不少于 60%。
4. **明细表**：`DataTable`。

### 4.3 例外页面

- **场景驾驶舱**：首屏使用稻田数字孪生场景横幅，展示场景编号、中文场景名、最近观测日期和地图/预警入口。横幅背景必须使用 CSS 渐变、SVG 或程序化图形，不使用来源不明的真实图片。
- **场景驾驶舱首屏判断区**：横幅右侧固定展示“当前孪生健康度 + 预警待核查数量 + 最近观测日期”，并提供 `查看地图` 与 `处理预警` 两个主路径入口。健康度是首屏最强数字，避免与下方 KPI 平铺竞争。
- **场景驾驶舱 KPI**：横幅下方使用 4 个支撑指标卡，固定覆盖地块数量、指标数量、预警数量和观测天数；孪生健康度只在横幅判断区突出展示。数字必须突出，说明文案不超过两行。
- **场景驾驶舱概览模块**：关键指标概览固定优先展示作物长势、叶绿素、氮、pH、LAI，包含最新值、单位、近 7 次趋势和状态；风险状态分布必须使用 `正常 / 关注 / 预警 / 严重` 四级；区域状态至少展示试验一区和试验二区的地块数量与预警数量；重点关注地块必须可进入地块画像。
- **Cesium 地图孪生**：地图必须是视觉中心，最小高度 560px，右侧附 320-360px 详情面板。
- **地块画像**：顶部使用横向摘要卡作为单地块数字档案入口；主体为基础信息 / 指标快照 / 指标趋势三栏；底部为观测批次记录、预警与建议、地块备注。
- **指标对比**：筛选 + 5 个 KPI 卡 + 地块排行图 + 区域对比 + 状态分布 + 明细表 + 指标说明。排行图、状态分布和表格必须使用统一四级状态色。
- **预警分析**：5 个风险统计卡 + FilterBar + 类型/严重程度分布 + 预警地块地图 + 最新预警列表 + 预警明细表。
- **系统说明**：说明型页面，不再采用“搜索区 + 文档目录表”为主结构；应作为项目说明中心，包含平台定位、当前数据说明、数字孪生构建流程、当前功能、数据来源与生成方式、系统边界、未来演进方向、文档索引和克制页脚。

## 5. 组件规范

所有页面必须复用 `src/components/base/` 的公共组件，不允许私有重复实现。`src/components/ui/` 只作为 shadcn-vue 源码组件层，为 `base` 组件提供按钮、卡片、弹层、表格、选择器、骨架屏等基础能力；页面层不要绕过 `base` 大量直接拼装 `ui` 原子组件。

### 5.1 PageContainer

- 顶部标题区：标题 22px Bold + 副标题 13px muted。CTA 放在右侧。
- 标题与下方块的间距 20px。

### 5.2 SidebarNav (`AppSidebar`)

- 白底，宽 240px。
- 顶部品牌：绿色方形 logo（主色渐变）+ 平台名 + 副标题。
- 链接：左 padding 14px，行高 44px，左侧 3px 高度 24px 的指示条（默认透明，激活态主色）。
- 激活态：背景 `--rf-primary-soft`，文字 `--rf-primary`，左侧指示条显示。
- 悬停态：背景 `--rf-surface-soft`，文字 `--rf-text`。
- 底部仅显示版本号，不放装饰卡片。

### 5.3 AppHeader

- 左侧：当前页面标题 + 副标题（由路由 meta 提供）。
- 右侧固定四件套：`天气（静态 26°C ☀ 晴）` → `通知 Bell（带角标）` → `文档 QuestionCircle` → `用户头像 + 角色名`。
- 不放置全局筛选器。所有筛选器在各自页面的 `FilterBar` 中。

### 5.4 StatCard

- 高度 108px，左圆形 tinted icon（44px），右侧三段：label / value / note。
- value 字号 28px Bold 800；label 13px muted；note 12px soft。
- 圆形图标背景 `color-mix(in srgb, var(--tone) 14%, white)`，图标颜色 `var(--tone)`。
- 6 种 tone 见 §2.5。

### 5.5 ChartCard

- 顶部 padding `16px 20px`，标题 16px + 副标题 12px。
- 图表区域 padding `16px 20px`。
- 卡片整体使用 `var(--rf-radius-lg)` 圆角，描边 `var(--rf-border-soft)`，背景白。

### 5.6 FilterBar

- 浅灰底 `--rf-surface-soft`，描边 `--rf-border-soft`，圆角 12，padding `14px 16px`。
- 控件之间间距 12px，右侧放 `查询`（`type=primary`）+ `重置`（描边款）。
- `FilterBar` 只负责布局容器，不依赖 Ant Design Vue 的 Form、Select、DatePicker DOM 类名。筛选控件应优先使用 `MetricSelector`、`DateSelector`、`RegionSelector`、`SelectControl`、`DateRangeSelector` 等 `base` 语义组件。

### 5.7 StatusTag

- 胶囊圆角 999px，padding `2px 10px`，字号 12，字重 700。
- 4 级状态：背景使用 tint，文字使用主色。

### 5.8 MetricValueTag

- 显示 `值 + 单位`，按 quality_flag 映射的状态着色。
- 表格中使用紧凑款（padding 3px 8px），KPI 中使用大字款（28px+）。

### 5.9 DataTable

- 表头使用 `--rf-surface-soft` 背景，表头字号 13，字重 700。
- 行高 48px，行分割线 `--rf-border-soft`。
- 操作列固定在最右，使用描边款小按钮（如 `查看画像`、`定位地图`）。
- `DataTable` 基于 shadcn-vue table 源码组件和项目自定义分页/横向滚动实现，不再使用 `a-table`。为降低页面迁移成本，继续兼容现有 `columns`、`dataSource`、`rowKey`、`rowClassName`、`pagination`、`scroll` 和 `bodyCell` slot 传参。
- `DataTable` 的横向与纵向滚动由 `scroll.x` / `scroll.y` 控制，分页状态下传给 `bodyCell`、`customRender`、`customCell`、`rowClassName` 的 `index` 必须保持全量数据下标，避免页面联动和高亮在翻页后错位。

### 5.10 CesiumMapPanel

- 最小高度 560px（详情页可降低到 320px），地图容器圆角 12，溢出隐藏。
- 必须提供：左浮动工具条、左下图例、右下比例尺占位。
- 选中地块描边使用 `--rf-status-warning`，宽度 3，正常地块按 quality_flag 着色。
- 必须提供右侧地块详情面板。

## 6. 图表规范

### 6.1 通用配置

- ECharts grid 默认：`top: 32, right: 24, bottom: 36, left: 48`。
- `xAxis` / `yAxis`：`axisLine.show: false`，`splitLine` 颜色 `#EDF2EF`。
- `tooltip`：light 主题，圆角 8，描边 `--rf-border-soft`。
- `legend`：默认顶部居中，字号 12。

### 6.2 颜色

| 用途 | 颜色 |
|---|---|
| 主指标值（柱、折线） | `--rf-primary` `#15905D` |
| 次指标值 / 对比线 | `--rf-accent-cyan` `#0E9F8C` |
| 正常占比 | `--rf-status-normal` `#16A36A` |
| 关注 | `--rf-status-watch` `#C58B04` |
| 预警 | `--rf-status-warning` `#EA580C` |
| 严重 | `--rf-status-critical` `#DC2626` |

### 6.3 折线 / 柱状

- 折线：`smooth: true`，宽度 2.5，节点 `symbolSize: 6`，区域填充 `rgba(21, 144, 93, 0.10)`。
- 柱状：圆角顶部 4，宽度 28-40。

### 6.4 反例

- 不堆叠 5 个以上系列在同一图。
- 不使用彩虹色随机配色。
- 首页只放概览图（排行、分布、趋势），详情页才放解释性多系列图。

## 7. 地图规范

- Cesium 页面地图必须是视觉中心，最小高 560px。
- 地块边界使用 `--rf-border` 加 0.6 alpha 边线；选中态描边 `--rf-status-warning`，宽度 3。
- 地块填充按 quality_flag 状态色，正常地块使用主色 30% 透明度。
- 必须提供图例（4 级状态色块 + 文案）和右侧地块详情面板。
- 异常 / 严重地块在地图上必须高亮（增加发光描边）。

## 8. 文案规范

- 全部使用中文。
- 状态等级统一使用 `正常 / 关注 / 预警 / 严重`，禁止裸露后端字段（`outlier`、`missing`、`error`）。
- 禁用词：`数据导入中心`、`Excel 报告`、`source cell`、`源单元格`、`导入批次`（→ 用 `观测批次`）、`导入质量报告`（→ 用 `数据质量`）。
- 副标题和说明文案以 1-2 行为限，避免堆砌。

## 9. 后续约束

1. 新页面必须：
   - 使用 `PageContainer` 包裹；
   - 走全局 CSS 变量 `--rf-*`，不写死颜色值；
   - 状态展示走 `StatusTag` / `MetricValueTag` 与 4 级状态映射；
   - 数据页采用三段式布局；
   - 图表配色和 grid 走本规范默认值。
2. 修改视觉风格（颜色、间距、组件结构、布局骨架）必须先更新本文件，再改代码；同一次提交内同步。
3. 不允许在页面级 `<style scoped>` 中覆盖 token 颜色。需要新颜色时先在本文件登记并加入 `global.css`。
4. 新增组件进入 `src/components/base/` 前必须在本文件第 5 章登记其规范。
5. CHANGELOG 必须记录视觉规范的每次修改。

## 10. Cesium 地图孪生页面规范

- 页面定位：`Cesium 地图孪生` 是系统核心空间分析页面，地图必须是首屏视觉中心；右侧详情、下方趋势图、关键指标表和最新观测记录只用于解释地图状态。
- 布局：主体使用 `地图主区域 + 右侧详情面板 + 下方分析区`。地图区域最小高度 620px，宽度优先占满主列；右侧面板宽度 320-360px；下方分析区采用左趋势图、右关键指标表、下方观测记录表。
- 顶部筛选：指标、日期、区域、查询、重置放在地图内部顶部浮层。浮层使用白底半透明、轻阴影、紧凑间距；查询按钮使用 `--rf-primary`，重置按钮使用白底描边。
- 移动端地图筛选浮层必须压缩为紧凑换行布局，地图工具按钮应避开筛选控件，不得遮挡查询、重置、指标、日期或区域控件。
- 地图渲染：地块 polygon 填充使用当前指标色阶或质量状态；缺失数据使用灰色低透明度；预警/严重使用橙色或红色突出；选中地块使用亮色描边和弱发光；地块编号必须显示在 polygon 中心。
- 图例：地图左下角固定显示当前指标名称和单位、低值到高值色阶、无数据、地块边界、预警/严重说明，不遮挡主要地块。
- 地图工具：保留缩放按钮，并提供定位选中地块、图层透明度、回到默认视角。工具按钮统一白底、8px 圆角、轻阴影、图标化表达。
- 详情面板：点击地块后展示状态标签、地块编号、区域、名称、面积、品种、最近观测、数据来源、观测批次；当前指标数值和较昨日变化必须突出显示。
- 图层控制：右侧下方使用项目语义开关组件，底层逐步迁移为 shadcn-vue / Reka UI 实现；包含地块边界、当前指标渲染、预警地块、区域边界；不提供测距、绘制、编辑、上传或真实 GeoJSON 导入入口。

## 11. 地块画像页面规范

- 页面定位：单个地块的数字档案页，展示基础信息、指标状态、趋势变化、观测批次和预警建议。
- 路由：`/plot-detail/:plotId?`，从地图页点击"查看画像"进入，携带 plotId 参数。

### 11.1 顶部页面标题与摘要卡

- PageContainer 标题使用 `地块画像 / {plot_code}`，副标题固定为“全面了解单个地块的基础信息、指标状态与变化趋势。”，右侧放“返回地图”按钮。
- 摘要卡使用 `.panel` 横向容器，左侧展示地块编号（28px 主色粗体）+ StatusTag + 地块名称 + 所属区域；中部用分隔列展示面积、品种、最近观测、数据来源和观测批次；右侧固定“定位到地图”主按钮。
- 摘要卡是页面视觉入口，不再叠加 StatCard 行；信息列可在窄屏折行，但不得挤压到不可读。
- “定位到地图”链接到 `/map-twin?plotId=xxx`，用于地图页尽量选中当前地块。

### 11.2 三栏主体布局

```
| 260px 基础信息 | 弹性宽 指标快照 | min 320px 趋势图 |
```

- **基础信息**（左 `.panel`）：dl 列表展示地块编号、名称、区域、面积、品种、播种/插秧/成熟期、来源、批次、创建时间。缺少真实后端字段时使用带“（模拟）”后缀的安全演示字段。
- **指标快照**（中间无边框区）：使用 `.metric-grid` auto-fill 网格（最小 180px），固定优先展示作物长势、叶绿素、氮、磷、钾、pH、有机质、盐分、LAI、株高、成熟期预测。每个 `.metric-snap` 卡片包含指标名、StatusTag、值+单位、较上次变化（箭头+百分比）。左侧 3px 状态色边条区分等级；缺失指标显示“暂无数据”。
- **趋势图**（右 `.panel`）：顶部标题 + 指标选择器，下方时间范围（近7/15/30天/全部），图表使用折线+区域填充。支持 `markArea` 显示正常范围。

### 11.3 底部三栏

- 左侧主列：`DataTable` 观测批次记录（批次编号、日期、来源、指标数、质量状态、备注）。当演示数据只有一个批次编号时，可按观测日期聚合展示最近记录，但批次编号必须保持真实 API 字段值。
- 中间列：预警与建议面板，包含预警列表（StatusTag + 指标 + 说明 + 日期）和建议措施（简洁谨慎，不编造农艺处方）。
- 右侧列：地块备注卡。当前阶段可以只展示空状态占位；如提供编辑，必须明确是前端临时状态还是后端持久化。

### 11.4 模拟数据字段

后端当前不提供面积、品种、播种日期等字段。前端使用安全模拟占位值，标注"（模拟）"后缀。不伪装为真实数据。

### 11.5 联动

- "定位到地图" → `/map-twin?plotId=xxx`
- "返回地图" → `/map-twin`
- 地图页接收 `plotId` 查询参数后，应尽量在加载图层后选中该地块并刷新右侧详情。
- 预警列表 "查看全部" → `/warnings`

## 12. 指标对比页面规范

- 页面定位：多维度指标分析页，用于回答当前指标在不同地块之间的差异、优秀地块、需关注地块、区域差异和异常地块占比。
- 页面标题由 `AppHeader` 的路由 meta 提供，标题为 `指标对比`，副标题为“多维度指标对比分析，发现地块差异与异常。”
- 筛选区使用统一 `FilterBar`，包含指标选择、观测日期、区域、查询、重置。查询按钮使用主绿色，重置按钮使用白底描边；筛选区下方用一行弱提示展示参与对比地块数量。
- KPI 行固定为 5 个 `StatCard`：地块总数、指标均值、最高值、最低值、异常地块数。最高值和最低值必须在 note 中展示地块编号与区域；异常地块数使用 red tone，但只使用状态 tint，不做高饱和告警大屏样式。
- 主可视化区使用三列：左侧排行图占主要宽度，右侧为区域对比和状态分布。窄屏按排行图、区域对比、状态分布顺序纵向堆叠。
- 地块排行图使用柱状图，按当前指标值排序；正常、关注、预警、严重分别使用 `--rf-status-normal`、`--rf-status-watch`、`--rf-status-warning`、`--rf-status-critical`；图中显示均值参考线。柱子点击应进入地块画像或定位地图。
- 区域对比卡至少展示试验一区、试验二区的平均值、最高值、最低值和地块数量。若后端未返回区域统计，前端可基于当前对比列表聚合，不新增 API 字段。
- 状态分布图使用环形图，中心显示总地块数，图例展示四级状态的数量和占比；颜色必须沿用 §2.2 状态色。
- 明细数据表使用 `DataTable`，字段包括排名、地块编号、地块名称、区域、当前指标值、较均值差值、较昨日变化、状态、数据来源、观测批次、操作。状态使用 `StatusTag`，指标值使用 `MetricValueTag`，涨跌样式克制使用红绿文字与箭头。
- 操作列固定使用小号描边按钮：`查看画像` 跳转 `/plot-detail/:plotId?`，`定位地图` 跳转 `/map-twin?plotId=xxx`。
- 指标说明放在表格下方，优先读取指标字典中的指标名称、单位、类别、正常范围和说明；指标字典缺少说明时显示“指标字典暂未配置说明。”，不得编造过多解释。
- 空状态：无对比数据时显示友好空状态；指标不存在时提示“未找到指标”；日期无数据时提示“当前日期暂无观测数据”；API 请求失败时使用统一错误提示。

## 13. 预警分析页面规范

- 页面定位：系统中的“风险诊断中心”，用于汇总数据异常与农情风险、查看风险类型和严重程度、定位风险地块、浏览最新预警与谨慎建议。
- 页面标题由 `AppHeader` 路由 meta 提供，标题为 `预警分析`，副标题为“识别数据异常与农情风险，辅助科学决策。”
- 顶部固定使用 5 个 `StatCard`：预警总数、严重预警、受影响地块、受影响指标、最新预警时间。严重预警使用 red tone，但只使用浅色 tint；最新预警时间必须展示日期和简短事件说明。
- 筛选区使用统一 `FilterBar`，包含指标、区域、预警类型、严重程度、日期范围、查询、重置。查询按钮使用主绿色，重置按钮使用白底描边；筛选区保持紧凑，不得挤压主可视化区。
- 主可视化区采用三列结构：左侧为预警类型分布和严重程度分布环图，中部为预警地块分布地图，右侧为最新预警列表。窄屏按地图、分布图、最新预警顺序纵向堆叠。
- 预警类型分布环图展示“数据质量预警 / 农情状态预警 / 趋势变化预警”，中心显示总预警数；严重程度分布环图展示“关注 / 预警 / 严重”，颜色沿用 §2.2 状态色。窄卡片内不得使用会挤压圆环的 ECharts 内置侧边图例，应使用图下方紧凑图例展示名称、数量和占比。
- 预警地图复用 `CesiumMapPanel`，地块按严重程度着色：严重 `--rf-status-critical`、预警 `--rf-status-warning`、关注 `--rf-status-watch`、正常 `--rf-status-normal`、无数据 `--rf-status-empty`；预警页地图应使用更紧凑的初始视角，让风险地块成为主体。地图必须显示地块编号和图例，不新增编辑、测距、绘制或上传能力。
- 最新预警列表展示最近风险事件，每条包含 `StatusTag`、预警标题、日期、地块编号和区域。点击预警后应选中地图地块，并高亮下方表格对应行；“查看更多”定位到预警明细表。
- 预警明细表使用 `DataTable`，字段包括日期、地块编号、地块名称、区域、指标、预警类型、严重程度、预警描述、建议措施、操作。状态使用 `StatusTag`；描述和建议措施可单行截断并使用 Tooltip 查看完整内容；操作列使用小号描边按钮。
- 操作列固定为 `查看画像` 和 `定位地图`：`查看画像` 跳转 `/plot-detail/:plotId?`，`定位地图` 跳转 `/map-twin?plotId=xxx`。
- 后端当前 `missing / outlier / error` 等技术字段不得直接暴露给用户。页面可在前端语义映射为中文风险类型、严重程度、风险描述和谨慎建议；如未来新增 API 字段，必须同步更新 API、schema、测试和文档。
- 建议措施必须克制：优先使用“复核田间观测情况”“结合灌溉、施肥和田间管理记录综合判断”“持续关注后续观测变化”“检查数据采集链路是否存在缺失”等表达，不编造不可验证的农艺处方，不做 AI 医生式诊断。
- 空状态：无预警时显示“当前筛选条件下暂无预警”；API 请求失败使用统一 `ErrorState`；地图数据为空时显示友好提示，筛选后无结果不得出现页面空白。

## 14. 系统说明页面规范

- 页面定位：`系统说明` 是项目说明中心，不是普通文档链接列表。页面应解释平台定位、演示数据来源、数字孪生构建逻辑、当前功能、当前边界、未来演进和文档索引。
- 页面标题：必须使用统一 `PageContainer` 标题区，标题为 `系统说明`，副标题为 `了解平台定位、数据来源、功能边界与未来规划。`；路由 meta 与页面标题保持一致。
- 顶部结构：使用两列布局，左侧为平台定位大卡片，右侧为当前数据说明卡。大卡片只使用 CSS 渐变或程序化图形，不引入来源不明图片；文案保持科研展示、项目汇报、教学演示语气，不写商业营销话术。
- 平台定位卡片：科研展示、项目汇报、教学演示三项使用与 `StatCard` / `InfoCard` 一致的浅色卡片、圆形 tint 图标、13px 说明文字和统一阴影，不做深色大屏或宣传页样式。
- 当前数据说明：数据模式、场景 ID、地块数量、指标数量、时间范围、预警数量应优先来自后端标准化 API；必须明确当前数据由程序生成，不是真实采集数据，不包含真实客户数据或可识别来源材料。
- 流程卡片：数字孪生构建流程使用横向卡片，包含序号、图标、标题和一句说明。流程固定表达为稻田地块实体、程序生成边界、构建数字对象、绑定多源指标、可视化与分析、预警与辅助决策，强调数字孪生是地块对象、空间边界、指标时序和预警分析的组合。
- 说明型分区：当前系统功能、数据来源与生成方式、当前系统边界、未来演进方向使用四列或响应式两列说明卡。每项内容使用短句，避免堆叠长段落。
- 边界说明卡：使用浅红色背景或红色左侧图标表达限制，语气克制明确。必须说明不做 Excel 导入，不做 GeoJSON、PDF、图片等文件导入，不做数据导入中心与导入报告，不保存真实客户数据，不做复杂三维资产与高级空间分析，不做 AI 决策自动化处方推荐。
- 未来演进卡：使用浅绿色列表表达未来方向，必须避免写成已完成功能。可包含 PostgreSQL + PostGIS、设备或传感器接入、更多作物与指标、预警规则与风险评估、报表能力、多项目多角色、Docker + Nginx 生产部署。
- 文档索引：使用文档卡片网格替代表格目录。每张卡展示文档键名、中文名称、简短用途和“查看文档入口”。若前端无法在线打开本地 Markdown，只能展示仓库路径或说明抽屉，不得伪造在线跳转。
- 页脚：可显示 `稻田智研平台 © 2025`、版本号和“用于科研展示与教学演示”，内容保持克制。
- 响应式：桌面优先两列/三列/四列布局；窄屏按内容顺序纵向堆叠。流程连接线在窄屏隐藏，文本不得溢出卡片。
